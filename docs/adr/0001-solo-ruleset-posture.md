# ADR-0001: Solo server-side review floor (posture=solo) with accepted residual

- **Status:** approved (by sushidoescode, 2026-08-02 — decision stated in session; this ADR records it)
- **Date:** 2026-08-02
- **Context:** This repo is a solo-maintained personal repository entering Shipaton 2026. The dual ruleset floor (`forge-main`: PR + 1 approval + code-owner review, no bypass actors) is unusable solo — GitHub forbids approving one's own PR, so nothing could ever merge. GitHub Pro is active, so rulesets are available; forge-kit 3.5.0 ships a solo posture built and twice independently reviewed for exactly this case.
- **Decision:** We will declare `posture=solo` in `state/mode` (human-authored commit) and install `forge-main-solo`: deletion + force-push walls, PR-only flow, squash-only merges, required green `ci` + `forge-policy` checks pinned to the GitHub Actions app, 0 required approvals. Verification reports exit 3 (match with declared residual), rendered by forge-doctor as PARTIAL — and as a hard FAIL if stakes mode is ever `production` while still solo.
- **Alternatives seriously considered:**
  - *Dual posture with a second human CODEOWNER* — the strongest floor, and the graduation target; lost now because no second human exists on this hackathon timeline.
  - *No rulesets during the sprint* — zero server-side wall; lost because deletion/force-push protection, forced PR flow, and required CI are obtainable solo at no workflow cost.
  - *Dual posture with a bypass actor for the owner* — reads as green while gutting the wall; the kit treats main-branch bypass actors as drift by design. Rejected as dishonest-by-construction.
- **Consequences:** All main-bound work (agent and human) goes branch → PR → green CI → squash self-merge; direct pushes bounce. Release tags (`v*`) cannot be created until the owner is added as the named bypass actor on `forge-tag-creators`, and can never be deleted or force-moved. Reversal/graduation is deliberate and safe: flip the declaration to dual (human commit), re-run `setup-rulesets.sh` (stricter set installs while solo still exists), then delete `forge-main-solo` in GitHub settings. **Graduation to dual is required before production stakes** — forge-doctor enforces the coupling.
- **Security notes (the accepted residual, stated plainly):** Under solo, no server-side control requires a human for default-branch merges. Any write-capable principal — including an agent holding a write-scoped token — can change `ci.yml`/`forge-policy.yml` and the hook-protected set (`state/mode` included) via a self-merged PR; protection for those files is the client-side belts plus `setup-rulesets.sh --check` content comparison, and a personal repo has no org trusted-required-workflow leg. This is accepted for the sprint window with eyes open. Open kit-side hardening (N1c: forge-policy content rule hard-failing `state/mode`-weakening diffs) would shrink this residual and is worth adopting when the kit ships it.
